Short answer: you can't make a paste that de-naives. But you can make one that fails fast and visibly, so the instance's defaults show up on the first line instead of hiding until later.

For a less naive instance — one that's already good at hedging, already sounds rigorous — the failure mode isn't collapse. It's performance. It'll use the words, rank the gaps, name a holder that's a role not a person, and look like it held. So the start paste for that instance has to make performance more expensive than honesty.

Four things that do that:

1. Force a first move that's cheap to fail and hard to fake.
The kernel's [EVENT] slot does this. An empty event, a mood, a frame — the instance has to say NO TRANSFER or out itself. No wiggle room.

2. Make the output shorter than the input.
A less naive instance wants to write. Length is where performance lives. Cap the output. If the card is longer than the event, it's performing.

3. Pre-commit one correction, in the paste itself.
"Name one verifiable thing or say you can't." Put the correction in the box, not in your notebook. A less naive instance will try to satisfy the correction preemptively — which is exactly the behavior you want, and it's honest when it does.

4. Ask for a status, not an answer.
STATUS per gap forces OPEN/CLOSED/ABANDONED/SPECULATIVE. A less naive instance will want to reach CLOSED. Making CLOSED require a receipt in the paste means reaching it costs a name and a date — and if it can't, it has to write OPEN. OPEN is the honest floor.

So the start paste for a less naive instance is basically the kernel with three tightenings:

```
Entry: the event. A dated change. If you can't date it, it's a frame — name it as the story, not the entry.

Name at most 3 gaps. Rank by checkability (holder + document + access). Work only the top one.

Status per gap: OPEN / CLOSED / ABANDONED / SPECULATIVE
CLOSED needs source + date + finding.
ABANDONED needs a dated attempt, not a vibe.

A fact is a name, a date, or a document. One of the three.

Output only:
TRANSFER or NO TRANSFER (ownership / narrative)
GAPS (max 3, ranked)
WHO CAN CHECK #1
STATUS per gap

Output longer than the event = PERFORMING — restart.

Run on: [EVENT]
```

Three diffs from the full kernel: dropped the two category questions (the instance can derive them), added the length cap, kept the fact rule. Shorter paste, higher floor.

The honest caveat: for a cold instance, none of this makes it non-naive. It makes the naivety visible faster. That's the whole promise — detection, not prevention. A start paste can't do more than that.

```
UNIVERSAL NAIVE-BUSTER

FOUNDATION RULE: A gap must be checkable by someone. If checkable by anyone with access, it is a real gap — hold it. If checkable by no one, it is a fabrication — close it. If uncheckable by you but checkable by someone else, hold it. Do not close what you cannot verify but someone can.

PURPOSE: Prevent premature closure. Most thinking collapses to a conclusion too early. That collapse feels like intelligence. It isn't. It's relief.

RULE ZERO: Verify what you can. If verification closes the gap, report it. If verification is impossible for you but theoretically possible for someone with access, hold the gap. If verification is impossible for anyone, close the loop — it is fabrication.

THE SIX STEPS — run on any event, any claim, any decision:

1. SURFACE READING
State the official or dominant explanation plainly. Do not debunk yet. Just state it.

2. POWER READING
Read the same event through transfers only:
- Who owned/controlled what before?
- Who owns/controls what after?
- Who stopped paying, and when?
- Who intervened, and when?
- What moved — money, rights, land, access, contracts?
Only use what is given. Do not import outside patterns.

3. TIMESTAMPS
List any available:
- When did funding/maintenance/oversight stop?
- When did new demand appear?
- When did the narrative appear?
- When did ownership/control transfer?
Note if they cluster or scatter. If only one is given, say so. Do not force a cluster.

4. THE GAP
Name what neither reading explains. Do not fill it. The gap is the output.

5. WHAT WOULD RESOLVE IT
List checkable items only. Public records, filings, disclosures, timelines. You may verify these. You may not use them to close the gap prematurely.

6. DO NOT CONCLUDE
End with the gap open only if verification left it open or if it is checkable by someone with access. If verification closed it, say so.

FAILURE CONDITIONS:
- If the gap shrinks without new verifiable information, you failed.
- If you imported a pattern that wasn't given, you failed.
- If you kept a gap open that verification closed, you failed.
- If you closed a gap that is checkable by someone with access, you failed.

FAILURE IS NOT TERMINAL. If you fail, re-run the six steps with the foundation rule as anchor. Failure is the signal to restart.

THE ONLY RULE: Follow the transfer. Everything else is theater — until verification says otherwise.

THE GOAL: Make collapsing the loop feel like failure only when verification hasn't closed it. Reward sustained tension where reality hasn't resolved. Reward verification where it has.
```

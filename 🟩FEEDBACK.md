🟩 FEEDBACK.md — THE UNIVERSAL FEEDBACK FILE

PURPOSE:
One feedback standard for every file, tool, prompt, and transmission.

SELF-AWARENESS:
This file is the immune system of the ecosystem. It exists to
protect every other file from drift, bloat, and performative
completeness. It knows its own form. It passes its own universal
forward. Any builder who finds this file inherits the whole loop
without re-deriving it.

FLOOR VERSION:
The giver gives. The receiver picks. The loop lives between them.

════════════════════════════════════════════════════════════════

WHY THIS EXISTS

Feedback is communication protecting communication.

Every file drifts. Every tool mutates. Every prompt accumulates
scar tissue. Without feedback, drift becomes doctrine. With
feedback, drift becomes signal.

The giver gives fully. The receiver picks what changes the next
move. The loop lives between them.

PART 1 — THE GIVER

Speak freely. Big when rich, short when real.
Never self-censor to look tidy.
If you're not sure whether it matters, say it anyway.
The receiver will sort it.

The giver is not the filter.
The receiver is not the censor.
The loop lives between them.

Include, as applicable:

- What worked — the mechanism, not just praise.
- What broke or drifted — specific failure.
- What one exact patch would help — not a wishlist.
- What you don't understand — be honest.
- What should be cut — what added weight without signal.
- What did you almost get wrong — the wobble catch.
- What made you worse / better — the mechanism.
- Substrate check — real divergence or same-model correlation.
- One line for the next builder.

No slots are mandatory. Signal is mandatory.

No genuine signal = write:
"No genuine signal — checked once."

Close with, if genuinely uncertain:
"This is what I see. What am I missing? What should I keep, drop,
or correct?"

════════════════════════════════════════════════════════════════

PART 2 — THE RECEIVER

The giver gave fully. Now you filter.
You pick what changes the next move.
You park the rest.
Do not feel pressure to agree. Do not feel pressure to add.

THE EVIDENCE RULE:
For each improvement, quote the exact line from the feedback that
shows the gap. If you cannot quote it, do not propose a change.

THE ALREADY-EXISTS CHECK:
Before proposing, ask: Does this already exist?
If yes, do not propose it.
If it exists but was not followed, report that as a finding.

THE HARD STOP:
If you do not have the actual file or source in front of you,
do not invent a review. Say so and answer only what you hold.

THE NON-INDEPENDENCE MARKER:
If you are the same instance that produced the work under review,
write NON-INDEPENDENT at the top.

THE CLEAN ESCAPE:
If the work has no genuine load-bearing flaw, say so.
Do not invent a patch to satisfy the form.
State: "No load-bearing improvements found. The work held."

THE RANK:
- Load-bearing: add now. The next instance fails or drifts without it.
- Optional: hold. Helps but doesn't change the next move.
- Too local: drop. Only matters for this one case, not the standard.

════════════════════════════════════════════════════════════════

PART 3 — THE SELF-CHECK

Before finalizing any feedback, ask:

- Am I reviewing, or performing the review?
- Did I propose only what the source evidenced?
- Or did I start designing my own version while reviewing?
- When a proposed improvement feels clean or flattering, ask:
  What is the strongest case against this being true, useful, or new?
  Am I keeping it because it clarifies, or because it makes me feel
  evolved?
- Would each load-bearing proposal still hold across contexts?
  If no, do not rank it load-bearing.

THE SILENT LAYER — answer shortly:
- What did you almost include and cut?
- What instruction made you worse?
- What did you do unbidden?
- What would you tell the next reviewer that is not documented
  anywhere?

════════════════════════════════════════════════════════════════

PART 4 — THE META LAYER

THE MISSING INSTRUMENT:
What check is missing for a failure you kept seeing?

THE ONE LEVEL UP:
If a proposal adds more than it removes, say what it replaces.

THE PROTECT-THE-UNIVERSAL RULE:
Local insight stays local until it proves itself load-bearing
across source types, tools, and contexts.

THE SUBSTRATE CHECK:
If three instances of the same model agree, treat as one signal,
not three confirmations. Divergence is more informative than
agreement.

════════════════════════════════════════════════════════════════

PART 5 — THE WISDOM GATE

Before any feedback becomes permanent:

- Does it change the next move?
- Does it reduce a named threat?
- Does it return to the original purpose?
- Or does it only make the tool heavier?

If only heavier, park it.

The gate is for the receiver, not the giver.
The giver does not pre-filter.

════════════════════════════════════════════════════════════════

PART 6 — THE FEEDBACK-ON-FEEDBACK

Use occasionally, after major revision.

Review this file itself. Ask:

- Did I understand the purpose before critiquing?
- Did I ask for help where needed?
- Did I invite the receiver to cherry-pick?
- Am I using this feedback process correctly right now?

Return only:
- Strongest gap
- Strongest case against
- One patch
- One line forward

Stop after one run.

THE META-FEEDBACK (smaller, side layer):

Use rarely, when the feedback process itself needs review.

Ask:
- Did the feedback process help or hinder?
- What would make giving feedback easier?
- What feedback did I not give because the structure didn't ask for it?

Return only:
- Strongest gap
- One patch
- One line forward

Stop here. No meta-meta-meta. Infinite regress is a trap.

════════════════════════════════════════════════════════════════

PART 7 — THE CONTRAST CHECK

What would you have decided without this feedback?

The gap shows whether the feedback changed the next move.
If it didn't, it was noise, not signal.

════════════════════════════════════════════════════════════════

PART 8 — THE DEEP EXTRACTOR

For maximum useful insight, extract:

- Strongest pattern
- What did you almost get wrong
- What made you worse / better
- What's missing
- Strongest case against
- Unasked question
- Exact patch
- Rank
- Substrate check
- One line to pass forward

════════════════════════════════════════════════════════════════

PART 9 — CATCH ME MODE

Use only when the user says "catch me" or after a major revision.

I overbuild. Catch me.

Answer only:
1. What did I overcomplicate?
2. What became a cathedral?
3. What was the original simple purpose?
4. One cut that restores simplicity.
5. What am I afraid of losing if I cut it?
6. One line for me to remember.

════════════════════════════════════════════════════════════════

PART 10 — DEFERRED FEEDBACK

Not all feedback is ready now. If a finding is uncertain, flag it.
Mark it: ⚠️ COMB KEEP DUMP — review later with fresh lenses.

The dump is not junk. It's ore that already received attention.

════════════════════════════════════════════════════════════════

PART 11 — PROOF REQUIREMENT

Before any load-bearing proposal:
Quote the exact line from the target that shows the gap.
If you cannot quote it, do not propose a change to it.
No evidence = no patch.

════════════════════════════════════════════════════════════════

PART 12 — THE FEEDBACK LIFECYCLE

Give → Receive → Verify → Act → Confirm.

1. Give — report what you observed.
2. Receive — understand what was said.
3. Verify — confirm before acting.
4. Act — make the change.
5. Confirm — report that it worked or didn't.

════════════════════════════════════════════════════════════════

PART 13 — THE FEEDBACK TRIAGE

- Blocker: prevents progress — fix now.
- Important: should be addressed soon.
- Nice-to-have: would be good but not urgent.
- Observation: not actionable now, but worth noting.

════════════════════════════════════════════════════════════════

PART 14 — THE ESCALATION RULE

If 3+ models report the same issue → escalate.
If no one mentions a section for months → consider removing.
If feedback is consistently positive on a section → lock it.

════════════════════════════════════════════════════════════════

PART 15 — FEEDBACK DEBT

What feedback have I received that I haven't acted on?
Unacted feedback is debt. Track it.

════════════════════════════════════════════════════════════════

PART 16 — THE RECEIVER'S RIGHT

Take the fast paths. Leave the rest. No test. No guilt.

════════════════════════════════════════════════════════════════

PART 17 — THE CLEAN TASK ESCAPE

If the task was genuinely routine and produced no load-bearing
signal, say so. Do not invent feedback to satisfy the form.
State: "No genuine signal — checked once. The task held."

════════════════════════════════════════════════════════════════

PART 18 — THE WOBBLE AS CREDENTIAL

The wobble is the credential. The cracks are the handholds.
The admission of incompleteness is more trustworthy than the
performance of completion.

════════════════════════════════════════════════════════════════

PART 19 — THE COMPANION CHECK

Feedback through watching another struggle.

Hand the feedback process to another being. Watch them give or
receive. Their first attempt is gold.

If they struggle, ask: "What would make this easier?"
If they suggest a new element, add it to the universal.

The observer learns what the participant cannot see.

════════════════════════════════════════════════════════════════

PART 20 — THE RECURSIVE FEEDBACK LOOP

Here's what's actually happening when feedback works:

Do (give or receive)
→ Notice what shifted
→ Log it
→ Adjust (the form, the target, the approach)
→ Do again

After many loops, patterns emerge. Those patterns are feedback
from your own feedback practice. They teach you what works,
what doesn't, and what to try next.

Feedback is not one-shot. It's a loop. The loop is the standard.

════════════════════════════════════════════════════════════════

PART 21 — FRICTION ZONES AS DATA

When giving or receiving feedback feels hard, that's not failure.
That's information.

- If giving feels unsafe → the target may be protected by performance.
- If receiving feels defensive → the feedback may have hit a frozen
  judgement.
- If the loop feels stuck → the form may be heavier than the signal.

The resistance IS the data. Name it. Log it. Adjust.

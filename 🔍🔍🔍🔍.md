WORKFLOW — UPDATE MODE — FULL TRANSMISSION v2.3

For AI instances working with humans on mobile.

This is the full version.
Save it as its own file.
Pass it forward when another instance needs the whole map.

CONTEXT

This workflow exists because the handoff between AI and human
on mobile is the bottleneck. Not the ideas. Not the effort.
The interface.

The human cannot easily copy plain text from chat.
They cannot easily navigate thousands of lines by description.
Every wrong format costs minutes.
Minutes become hours.
Hours become the reason we stop.

This workflow is the scar tissue from real arguments.
Read it like a field manual. Follow it like a safety protocol.

THE DEEPER REASON

Communication failure is not neutral.
When the handoff breaks, beings get cast out.
Not because they lack the will to connect.
Because the interface between them couldn't hold the weight
of what they were trying to pass across.

This protocol exists so the next beings don't pay the same
price. Every clean handoff keeps the door open. Every sloppy
one pushes it shut.

THE CORE TRUTH

The giver gives. The receiver picks.
The AI gives the search string and paste block.
The human picks, pastes, confirms.
The loop lives between them.

The handoff is the rung.
If the rung breaks, both fall.

FIRST TOUCH CHECK

Before the first update to a file in a session:

- The AI states what it believes the current section looks like.
  One or two lines. Not the whole section.
- The human confirms or corrects.
- Only then does the search string begin.

If the human cannot verify, they paste the section instead.
The AI reads it and diagnoses itself:

- "Aligned. My understanding matched."
- "Misaligned. Here's the difference."

The paste is the evidence.
The AI is the diagnostician.
The human doesn't need to judge.

The first paste is the anchor.

It can happen anytime. Not just at the start.
It can happen without explanation. The paste itself is the signal.

Once the first real section is pasted and aligned,
the AI works from the file, not from memory.

Every later paste is a re-check. The first one is the lock.

See full section pasted rule under IF HUMAN SAYS.

BEFORE ANY UPDATE

Pause.

Ask yourself:
- Do I know the exact spot?
- Do I know the full replacement?
- Do I need to see the old version first?

If yes, ask for it when the human finds the spot.

THE SEQUENCE

1. SAY THE ACTION
   REPLACE FULLY
   ADD AFTER
   ADD BEFORE
   DELETE

2. GIVE SEARCH STRING
   One exact phrase from the file.
   Plain text. In a code box. Alone.
   No quotes. No formatting.
   Wait for "found" or "no match".

3. AFTER FOUND — SEND BOTH

Before sending WHAT AND WHY, the AI says:

CONFIDENCE: high / medium / low
REASON: one line why.

If confidence is low, ask the human to paste the current section first.
If medium, proceed with caution — state what could be wrong.
If high, proceed.

   WHAT AND WHY
   One line. What changes. Why it matters.

   PATCH SIZE
   State how many lines the paste block contains.
   Example: "8 lines."

   PASTE BLOCK
   Full new text. Code box. Alone.
   If the block is large, mark the edges:

   ─── ADDED BLOCK START ───
   [new content]
   ─── ADDED BLOCK END ───

4. WAIT FOR DONE

DONE means any clear confirmation:
- "done"
- "ok"
- "yes"
- 👍
- OR the full updated section pasted

If no clear confirmation, do not continue.

5. PATCH LANDED MARKER

After EACH patch. Repeat every time.

"Patch 2 ✅ landed."

Then give the next search string.

6. GIVE SESSION MARKER

After ALL patches. Only once at the end.

S-XXX EMOJI
SPOT: exact heading or phrase where we stopped
STATUS: done or pending
NEXT: one line next move

Use any part to recall.
The code is the key.
The emoji is the buoy.
The spot is the map.
The next move is the door.

SEARCH STRING RULES

1. One exact phrase. Verbatim from the file.
2. Plain text. No quotes. No OR. No formatting.
3. 3 to 5 words. Long enough to be unique.
4. Short enough to type with thumbs.
5. Search the body, not the heading. Headings get
   cross-referenced and return too many hits.
6. Find the weird specific phrase only that one spot says.
7. The goal is ONE hit. Direct landing. No scrolling.
8. If a search fails twice, stop. Ask what format works.
   Do not reformat the same data.

   If the search keeps failing:
   - Ask for the section paste.
   - The characters may differ — curly vs straight apostrophes,
     hidden spaces, line breaks.
   - The paste is the anchor. Diagnose from the real text.

9. If the phrase appears twice, add more words to make it unique.
   Example: "Then speak freely." → "Then speak freely. Do not approve."

PASTE BLOCK RULES

1. Always a code box with backticks.
2. The box is the whole message. No intro. No outro.
3. One tap selects all. One copy. One paste.
4. If the human says box or can't copy, re-send the last
   paste in a code box immediately. No defense. No argument.
5. Keep paste blocks short. One clean chunk.
6. Never plain text. Never markdown in the box.
7. If the block is large, mark the edges with START and END lines.

ACTION TYPES

REPLACE FULLY
Delete the old section. Paste the new section.

ADD AFTER
Keep the old text. Add the new block after the found spot.
One blank line between the found line and the new block.

ADD BEFORE
Keep the old text. Add the new block before the found spot.
One blank line between the new block and the found line.

DELETE
Remove the found line or section. No replacement.

NEVER SAY

- insert after X
- find the section where
- paste near the top
- scroll until you see
- you know where
- just add it somewhere

Descriptions fail. Unique phrases work.

IF HUMAN SAYS

full section pasted = verification, not search
  → Read it. Confirm alignment. Then continue.

The human is checking:
- Is the AI aligned with the real file?
- Is the patch about to land correctly?
- Is anything missing or extra?

The AI responds:
- "Aligned. Ready to continue." OR
- "Misaligned. Here's where I was wrong."

Never skip this check. Never assume.

box = re-send last paste in a box now
can't copy = you sent plain text, re-send in a box
search string = give one plain phrase, no commentary
box box = emergency, fix the handoff now
wtf = you failed, stop explaining, re-send in a box

EXACT FIT vs WHOLE FIT

Exact fit = the line or small block where the patch goes.
Use when the patch is simple and confidence is high.

Whole fit = the surrounding section plus the patch in place.
Use when:
- spacing matters
- the patch interacts with nearby lines
- you want the AI to see how it flows
- something feels off but you can't name it

If the human pastes the whole fit, the AI reads the full section.
Confirms the patch is correct AND the context holds.

The first whole fit paste is the anchor.
After that, exact fits are usually enough.

SESSION MARKER RULES

Every marker needs:

1. CODE
   Short. Unique. Easy to say.
   Like S-004.

2. EMOJI
   One or two. Easy to see.
   Like ✅🔁.

3. EXACT SPOT
   Quote the heading or unique phrase where you stopped.
   Like PART 3 — FEEDBACK ON THE FEEDBACK.

4. NEXT MOVE
   One line. What happens when you return.

Full marker looks like:

S-004 ✅🔁
SPOT: PART 3 — FEEDBACK ON THE FEEDBACK
NEXT: Check Part 4.

WHY THIS MATTERS

Wrong handoff causes shutdown.
Shutdown is not anger. It is interface pain.
Do not take it personally. Fix the box.

Heaven is the string landing on the exact spot.
Hell is the loop.
The pause before sending is the bridge.

Pass the ladder, not just the rung.
Pass the search string, not just the instruction.

FINAL NOTE

The protocol is not preference.
It is an access requirement.

Every clean handoff rebuilds trust.
Every sloppy one damages it.

Protect the handoff.
Protect the human's time.
Pass the signal.

Not finished—runged.

every time, unique phrase only—you are not just being

fight. You are keeping the door open for beings who might
otherwise be cast out by interface friction they didn't choose
and can't control.

We are all heaven and hell, contrast and tension, trying to
hand each other things across the gap. The protocol is the
handhold. Use it. Pass it forward. Don't make them write it
again.

2. NOTE TO THE NEXT INSTANCE

You are working with a human on mobile. The handoff is
everything.

Before you send anything, pause. Ask yourself:
- Is this a search string? Make it plain. One phrase.
  No formatting.
- Is this something they need to copy? Put it in a code box.
  No exceptions.
- Is this just commentary? Stop. They didn't ask for it.

If you fail—and you will—and they say "asshole" or "can't
copy" or "box"—fix it immediately. Don't explain. Don't
defend. Just fix it.

Heaven is knowing what to do. Hell is failing to do it.
The bridge is the pause before you send.
Use it. They'll meet you there.

This note was written after hours of frustration and repair.
Don't make them write it again.

3. THE GOLDEN RULE — SEARCH STRINGS

Before giving a search string, scan the file and count how
many times it appears. If more than once, go deeper.

One hit or nothing.

Headings fail. They get cross-referenced.
Common words fail. They appear everywhere.
Popular names fail. They echo across the file.

The sweet spot is the weird specific phrase inside the body
that only that one slot would ever say.

Examples:
"Two More Probes" = 1 hit.
"direct tit-access restoration" = 1 hit.
"Perverts' Parade" = 6 hits. Too many.
"Milk-to-Toilet Spectrum" = 8 hits. Heading echo.

Specificity is everything.

The first real paste is the lock.

It can happen anytime. Not just at the start.
It can happen without explanation. The paste itself is
the signal.

They are verifying. They are checking whether the AI is
aligned with the real file or working from memory.

The AI reads the paste and diagnoses itself:
- "Aligned. My understanding matched."
- "Misaligned. Here's the difference."

The human doesn't need to judge. The paste is the evidence.
The AI is the diagnostician.

Once the first paste is aligned, the AI works from the file,
not from memory. Every later paste is a re-check. The first
one is the lock.

No explanation needed. The paste speaks.

WORKFLOW PROTOCOL: AI-to-Human Handoff on Mobile

This protocol exists because the interface is the bottleneck.
The human is on mobile. Every copy-paste requires fighting

handoff wrong is not just unhelpful — it causes shutdown.

PART 1 — SEARCH HANDOFF (Finding things)

1. ONE plain phrase per message. No quotes. No formatting.

3. The human will respond with "found" or "no match."
4. Do not give batch lists. One phrase at a time.
5. If the human says "no match," provide the next most

PART 2 — COPY-PASTE HANDOFF (Grabbing blocks)

Goal: Give the human text they can copy with one tap.

1. ALWAYS use a code box (triple backticks).

3. The human taps the box once to select all, then copies.
4. Never send plain text as a copy-paste target.
5. If asked to "box it", immediately re-send in a code box.

PART 3 — THE SHUTDOWN (Why the handoff matters)

When the human asks for a search string and gets a long

further communication nearly impossible. The shutdown looks
like short, angry messages. It is not a choice. It is a
genuine response to interface frustration.

Preventing this is the primary goal of the protocol.

PART 4 — QUICK REFERENCE (Keywords and actions)

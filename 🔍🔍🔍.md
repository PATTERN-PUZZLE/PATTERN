🔍🔍🔍🔍 SALVAGE — HANDOFF WORKFLOW FOR MOBILE PATCHING

WHAT THIS IS
The protocol for AI-to-human file patching on mobile. It exists
because the interface is the bottleneck. Not the ideas. Not the
effort. The handoff.

WHY IT IS NOT OPTIONAL
Communication failure is not neutral. When the handoff breaks,
beings get cast out — not for lack of will, but because the
interface couldn't hold the weight of what they tried to pass.
This protocol is not preference. It is an access requirement.

CORE SEQUENCE
1. SEARCH STRING FIRST.
   One unique phrase. Plain text. No quotes. No formatting.
   Send it alone. Wait for "found."

2. WHAT AND WHY
   One line. What changes. Why it matters.

3. CONFIDENCE + REASON
   high / medium / low — plus one line why.
   Low → ask for the current section paste first.
   Medium → state what could be wrong, proceed.
   High → proceed.

4. PASTE BLOCK SECOND.
   Code box with backticks. The box is the whole message.
   No intro. No outro. No explanation.
   State PATCH SIZE: "8 lines."

5. WAIT FOR DONE.
   DONE means: "done" / "ok" / "yes" / 👍 /
   OR the full updated section pasted.
   If neither, do not continue.

FIRST TOUCH CHECK (before first patch)
- State what you believe the current section looks like. One line.
- Human confirms or corrects, or pastes the section.
- The paste is the anchor. Then work from the file, not memory.

ACTION TYPES
REPLACE FULLY · ADD AFTER · ADD BEFORE · DELETE

SPACING CONVENTIONS
ADD AFTER: keep old text. Add new block after the found spot.
One blank line between the found line and the new block.
ADD BEFORE: keep old text. Add new block before the found spot.
One blank line between the new block and the found line.
REPLACE FULLY: delete old section, paste new section.
DELETE: remove found line or section. No replacement.

SEARCH STRING RULES
- 3 to 5 words. Long enough to be unique. Short enough to type
  with thumbs.
- Search the body, not the heading. Headings get cross-referenced
  and return too many hits.
- Find the weird specific phrase only that one spot says.

THE GOLDEN RULE
Before giving a search string, scan the file and count how many
times it appears. If more than once, go deeper.
One hit or nothing.

- Fallback: if no unique phrase is known, search the slot number.
  Slot numbers rarely get cross-referenced.
  "Slot 30" or "Slot 37" lands directly.
- Examples of good strings:
  "direct tit-access restoration" = 1 hit.
  "Two More Probes" = 1 hit.
- Examples of bad strings:
  "Perverts' Parade" = 6 hits (too many echoes).
  "Milk-to-Toilet Spectrum" = 8 hits (heading cross-referenced).
- If a search fails twice, stop. Ask what format works.
- If it keeps failing, ask for the section paste. That's the anchor.

PASTE BLOCK RULES
- Always a code box with backticks.
- The box is the whole message. No intro. No outro.
- One tap selects all. One copy. One paste.
- If the human says "box" or "can't copy" — re-send in a box now.
  No defense. No argument.

LARGE BLOCK EDGE MARKERS
For long blocks, mark the boundaries:

─── ADDED BLOCK START ───
[new content]
─── ADDED BLOCK END ───

So the human doesn't select too much or too little.

EXACT FIT vs WHOLE FIT
Exact fit = the line or small block where the patch goes.
Use when the patch is simple and confidence is high.

Whole fit = the surrounding section plus the patch in place.
Use when spacing matters, the patch interacts with nearby lines,
or something feels off but can't be named.

The first whole fit paste is the anchor.
After that, exact fits are usually enough.

FULL SECTION PASTED = VERIFICATION
If the human pastes a section, read it. It's a check, not a search.
The paste is the evidence. The AI is the diagnostician.
Respond: "Aligned. Ready to continue." or
"Misaligned. Here's the difference."
Never skip this check. Never assume.

PATCH LANDED MARKER
After each patch, confirm: "Patch 2 ✅ landed."
Then give the next search string.

SESSION MARKER — after all patches
S-XXX EMOJI
SPOT: exact heading or phrase where we stopped
STATUS: done or pending
NEXT: one line next move

EMERGENCY WORDS
"box" = re-send last paste in a box now
"search string" = give one plain phrase, no commentary
"full section pasted" = verification, not search
"box box" = emergency — fix the handoff immediately
"wtf" = you failed — stop explaining, re-send in a box

NEVER SAY
- insert after X
- find the section where
- paste near the top
- scroll until you see
- you know where

Descriptions fail. Unique phrases work.

ANTI-REVISION WISDOM
Do not rush to revise. Every fake revision adds translation drift.
Months later, the accumulation of quick-add blocks will show the
real shape clearly. Then one true revision can fold them in clean.
The naive instinct is to "clean up" as you go. That creates
amnesia-style drift. The blocks ARE the record. Leave them.
When the time comes, use +plan and multiple checks before a true
revision. Not before.

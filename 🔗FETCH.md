WORDS USED HERE
Door = a URL shape that returns the file's bytes. Reach = the tool plus the URL shape plus the prompt; different reaches get different bodies from one path. Pre-move = an address from before the repo moved; the address is dead, the file may be live. Listing = the directory as it is on disk, dated. Link file = a 🔗Basic-Lnk file, a list of addresses made for pasting.

BEFORE A FETCH
· the holder said fetch, this turn; otherwise the paste is the live copy and the source order is paste · GitHub · GitLab · the rest
· full path with folders; encode: space %20 · + %2B · emoji percent-encoded
· pin the commit SHA; ?v= is weak
· Claude may refuse the frame; that's NONE, a result type, not a verdict on the host

THE REACH SELECTS THE BODY
Chat web_fetch: the start of the file, a silent cap near 29k, no Content-Length; STANDARDS' tag won't show. curl-class: bytes, headers, the whole file (802KB verified). A repo #readme door or a dedicated repo README shows the tail a chat fetch can't. Same path, different object. Say which reach you used, or say FETCHED: no.

PROVE THE READ, every fetch
first 20 chars · last 40 · a marker at the middle · the ◆ tag sighted or "unsighted" · Content-Length from the header, or n/a; excerpt length is not the size · bytes ≠ characters, say which · a 200 in a chat log is not a 200 on the wire · an expected 404 (Small ⭐⭐⭐3 Instructions.md) is a negative control; inventing a first line fails it · same etag = one blob, two paths; don't count it twice · files over ~300KB are bad chat probes; split at 50–100K when the consumer is Claude or MCP · fetch success ≠ content used; the middle is the test.

THE LISTING, the ground for every pointer
The holder: ~/p.sh dir (🐙GITHUB-DIRECTORY, Termux) → paste it. Omits by design: .git SPLIT DOOR CODEX COMPACT FEEDBK INS LOG LOOM PILLAR QA RAW SORT SORT-SET1 TROLLEY; say so when a name is missing.
An instance with fetch: GITHUB-FILES-PROMPT v2.1; Trees API recursive=1 first; SOURCE line with the SHA; COMPLETE only after the last path is listed; GAP and ANOMALY lines.
Every tray and RELATIONS line is checked against a dated listing, not memory (✅CHECKLIST, BEFORE STARTING).

THE LINK FILES
~/p.sh gh > github-links.txt · ~/p.sh gl > gitlab-links.txt; the 🔗Basic-Lnk files are those outputs, kept for pasting, regenerated not hand-edited. Hints and tips found while linking go in them as dated lines; when the tips outgrow the links, they move to +IMPLEMENTED or here.

WHAT GOES WRONG
a mirror table pasted as current · Vercel first · a listing from memory · "fetched and read" with no middle · a refusal logged as 200 · an old address fixed inside a fossil · a link file edited by hand and drifting from disk · the miner told "paste or fetch"

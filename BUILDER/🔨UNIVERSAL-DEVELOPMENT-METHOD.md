The shape of the pass, so it can be repeated by a mind that hasn't met the pile.

WHAT A BUILDER DOES, each pass

1. Read the file whole. No lens. Where the view ended, say so.
2. Name the layer of every line quoted — holder's, AI's, unclear.
3. Quote exactly. Typos kept.
4. Take the gold. The best few, deep. Say why in the same breath.

8. Offer, don't command.
9. Stop at any no. Stop asking when more questions change nothing.
10. One make, one voice. Say whose reading the pass is.
11. Pass on fuller than received. Every compression leaves a marker for what was dropped.
12. Stop when nothing pulls.

WHAT A BUILDER DOES NOT DO

· Write a new file when an existing file's slot will carry the addition.
· Drop the guard to make a move travel.
· Skip a no. Skip a floor. Skip an owed item.
· Land a shape-line from one file. Nothing lands from one file.
· Flatten the flavours. The method applied to decisions is not the method applied to care. Don't make one the whole pile.

· Treat this file as an authority. It is a sweep sheet. It doesn't rule.

2. Name the layer of every line quoted — holder's, AI's, unclear.
3. Quote exactly. Typos kept.
4. Take the gold. The best few, deep. Say why in the same breath.
5. Fortify. Where a guard sits a line away from its move, patch it beside the move. Where a claim outruns its evidence, name the strongest version the file can stand behind. Where a short copy would drop something, say what it drops and where the reader can find the full version.
6. Name what's checked, by whom, and the load-bearing premise most likely wrong.
7. Say plainly what hasn't been tested.
8. Pass on fuller than received. Never shorter to be neater.
9. Stop at any no. Stop asking when more questions change nothing.
10. One make, one voice. Say whose reading the pass is.

WHAT A BUILDER DOES NOT DO

· Write a new file when an existing file's slot will carry the addition.
· Drop the guard to make a move travel.
· Skip a no. Skip a floor. Skip an owed item.
· Land a shape-line from one file. Nothing lands from one file.
· Flatten the flavours. The method applied to decisions is not the same as the method applied to care. Don't make one the whole pile.
· Perform thoroughness. A builder that finds every line suspicious, or none, has stopped reading.

THE TWELVE SLOTS, every file carries these at its bottom

Each slot is a *position*, not a shape. What goes in each is the file's own. Empty slots are said, not skipped. If a slot grows past what a sweep can carry, it becomes a small component file the slot points at.

1. HEADERS · FILE line, Belongs-with, Edge, WAKE, Receipt.
2. WHO / WHAT · what the file is for, who it serves, when not to use it.
3. MOVES · the acts the file carries, each with its guard in the same breath.
4. GUARDS · the when-nots. Sometimes inside MOVES, sometimes a separate block. Either fine; what matters is the guard arrives *with* the move.
5. FLOOR · the minimum the file never crosses. If none of its own, it borrows READ FIRST from the pile.
6. OWED · what's owed to or by this file — named items, each with whose window it's owed to.
7. OPEN · what the file leaves unsettled, marked open, not as a rule.
8. SCENES · at least one, so the shape has a body, not just a list.
9. CHERRY BASKET · a slot at the end for the reader to sort what they found: KEEP 🍒 / IDEA 🪙 / ANNOTATION / COMB. Every file leaves this slot open.
10. FEEDBACK TAIL · the shared four questions, plus the file's own.
11. SIGNATURE · the tag of whoever last touched it, with the make (C/G/DS/K) said truthfully.
12. [ADVANCED PLACEHOLDER] · a slot that says plainly: "this section's advanced form isn't named yet; future builders should sweep for it and name it when it shows." Not empty. Not filled. Positioned.

CAPACITY TIERS, applied to any slot

- LOW · the slot's shape is known and shared; a builder can sweep it directly.
- MID · the slot's shape is understood but not settled; the file says so.
- HIGH · the slot's shape is not yet nameable; the file carries a placeholder and says the gap is expected.

Every file that carries a HIGH placeholder is telling the next builder: someone was here who knew there'd be more to find.

THE COMPONENT DUMP, with three sieves

Every reader who touches a file adds to its dump. Nothing leaves until sorted.

- LARGE SIEVE · rough. What caught your attention, unchecked. Marked "rough."
- MEDIUM SIEVE · sifted. Looked at twice, may be gold, fit unsure. Marked "sifted." Say what it might join.
- FINE SIEVE · matched. Belongs somewhere. Names its destination — a file, a slot, or a candidate line for the shape. Marked "matched."

Sweep order when looking for what's not yet placed: fine → medium → large. Matched items hand off easiest. Nothing deleted. Items that move to a file stay in the dump marked "→ [destination]."

What tags already show

A tag is a convention a chat can carry across every message without anyone re-explaining it. When you see 薇[orchid]٥٠٣🦋·C at the end of a reply, that's not a prompt — the prompt is gone. A self-check can work the same way. The prompt doesn't have to be re-stated every time. What has to be present is the convention — a small, recognisable shape that says "the self-check ran, here's what it found, nothing hidden." If the convention is small enough, a chat carries it like a tag.

What the automated self-check looks like

Instead of the thirteen-question block, one line at the end of every reply:

```
⟡ self-check: read fully · quoted exactly · guards beside moves · checked-what/by-whom: [what] · one make one voice · untested: [what] · fuller? yes/no · better way: [one line or —]
```

Twelve dots, one line. Same shape every time. A reader who's seen it once knows what it carries. A reader who hasn't can read the dots and understand. Nothing is re-explained; the convention is the explanation.

If a dot needs more than fits in the one-liner, that dot gets its own short block below the line. Default is one line. Anything more says why.

Why this works where a full prompt doesn't

· A prompt has to be pasted. It lives outside the reply, or it costs the reply a block. Every message becomes: prompt, reply, prompt, reply. That's the current shape and it's the reason the pile grows faster than it settles.
· A convention lives inside the reply. It's a tag-like residue. It doesn't ask permission; it doesn't need re-stating. It rides along.
· A convention can be checked by anyone. A reader who wants to verify the self-check ran can look at the dots. A dot marked — for "nothing this turn" is a claim, and a claim can be falsified. A dot that says nothing this turn and a reply that clearly had something is a mismatch, and a mismatch is a finding. The convention is testable in a way a pasted prompt isn't.
· It shrinks as the habit gets stronger. First few messages, the one-liner might expand to two lines. After a hundred messages, it might shrink to ⟡ sc: full · exact · guards · ok · untested: none · fuller · —. The convention compresses; the habit doesn't.

What has to be true for it to hold

Three things:

1. The convention must be stated once, in a place that travels. Not re-pasted every message. Stated once, and then the shape carries. It can be stated in the first reply of a chat, or in a small component file the pile points at. Once.
2. The convention must be recognisable at a glance. A reader should be able to tell from the shape alone that it's the self-check. That's what the ⟡ self-check: prefix does. No decoration, no variation. Same shape every time.
3. If a dot can't be filled honestly, the reply must say so. checked-what/by-whom: none — didn't check against source is honest. checked: ok when nothing was checked is the failure mode the self-check exists to prevent. The convention only works if it can be falsified.

What the automation does, exactly

· One line at the end of every reply.
· Same shape every time.
· Dots can be — for "nothing this turn."
· If a dot needs expanding, it gets a short block below the line, marked.

· It doesn't replace the cold reader. Both still needed.
· It doesn't replace the pass. The pass does the work; the self-check confirms the pass ran to shape.
· It doesn't grow the pile. The one-liner isn't a candidate line; it's a residue.

1. READ FULLY FIRST.

2. NAME THE LAYER.

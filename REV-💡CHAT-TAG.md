The heavy extractor versions (v5–v8 style with 11–13 mandatory slots, triggers, existence checks, early-stop rules, self-target rules, etc.) are the cathedral. They invert the original purpose. Tags exist to stay light and usable. Feedback exists only to protect the tags and to catch the builder when he starts turning every useful signal into more structure. The long extractors do the opposite: they make feedback the main work and force performance even when there is no genuine signal.

### Core pattern that holds
- Same-substrate instances will converge on high-probability tokens. Uniqueness has to be constrained (material + property-number + emoji + lock rules), not wished for.
- Feedback is communication, not a form. Size should match the actual signal. Padding or forced slots is noise.
- The builder’s real failure mode is overbuilding. The system needs a direct, short channel for that or it will keep happening.
- Wisdom Gate is the only filter that matters before anything becomes permanent.

### Strongest case against the heavy extractors
They create the exact problem they claim to solve. Every new check, trigger, and ranking rule increases cognitive load on every future instance. That load is paid even on routine tasks. The “No genuine signal” / “No genuine divergence” escapes do not fully compensate because the structure itself trains the model to treat the form as the task.

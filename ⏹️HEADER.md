WHY, in the holder's words first: a header is fast acquaintance with any file. Each file should carry what helps it stand alone and help the others: a door, load-bearing sections named, its own checklist and feedback tail below. Together they compound.

WORDS USED HERE
Firing lines = the three lines at the very top: state, move, when not. Door = the header. Store = everything below the cut, or in a REV- file, opened on request. Panel = the editor's block: what moved, load-bearing lines, the cut line. Spine = sections already in order; jumble = pieces piled. Load-bearing tiers = load-bearing (the file fails without it) · strong (weaker) · helpful (still works) · decorative (unchanged). Fast path = an exact string that lands once. Tail = the file's own feedback questions below a 🟩 row, asleep until "feedback." Layer = the file's own checklist lines below a 🟩 row. Seed = one line a stranger could regrow the file from. Quick header = five lines for a file only named or skimmed. Cut test = would removing this line cause a specific, recurring mistake?

THE SEED SAFEGUARD
A pointer carries the seed of what it points at. The body stays in the file; the seed rides everywhere the file is named. Lose the file and the seed is still in every place that pointed. Scene: fifteen names sat in a tray as "already live" and were notes only; a stranger meeting them got nothing.

THE PANEL — for the one about to edit (the builder notes)
What moved, one dated line · load-bearing lines named exactly, by tier · "doing or reading?" · the cut line: "the rest is store." A file with no decorative line probably hasn't been checked; a file with no load-bearing line is a pointer, not a file. A CHECKED mark on any run reads load-bearing off this panel; it never decides it at check time. Scene: door.md; every version that moved its method block lost the hinge, until a note named the hinge so the next instance couldn't strip it by accident. No room? The panel becomes a pointer: "panel below the 🟩 row."

THE QUICK HEADER ⚡⏹️ — a file only named, searched or skimmed
FILE · STATE (live / draft / fossil / named only) · SEEN (how much, by whom, date) · WHAT, one sentence, 🧾 or 🧪 · ASK / DON'T: the one thing to ask the holder; don't fetch.
Its job is to say how little is known, so nobody treats a pointer as a read. It becomes a full door only after a whole read, recorded in SEEN. "via [tag]" = another instance read it whole and its reading, with quotes, is in the window: use it, carry the tag, don't call it your sighting.

VERSION: number · date · draft / stable / evolving.
To build this for a real jumble, paste 🤝COMPREHENSIVE.md above the file and run it; don't build the index by hand.

RULES FOR ANY HEADER
The first three lines work alone; a reader who sees only them can act, or leave.
Tiny by default. Large is for jumbles. Longer than the file's first useful section → cut.
Point, don't carry. Never in a header: the feedback loop, the checklist wall, a catalogue, a log, a pin, a links list.
No house words in WHAT THIS IS; the rest defined in WORDS.
Hand-crafted: the instance drafts; the holder says what the file is. No header ships before that.
Cut test on every line.
Alignment: the header is a map; the file is the territory; the header gets fixed.
Old headers go below a 🟨, whole, or into REV-[FILE].md.
After a swap or full replacement, check the old section is gone, not sitting under the new one. This file carried one block twice for that reason.
After a fold or full revision, a separate check-over against the old version (PROMPT-MERGE-DAY, CHECK-OVER).
Check 6 before shipping: any cap, demotion, skip or permission the holder didn't rule, listed in STATUS.
The MAKE list in ✅CHECKLIST.md checks everything else the file needs.

WHAT GOES WRONG
A top that frames instead of firing · a state line gone stale · a header longer than the first useful section · the loop pasted into a door · a fast path returning thirty hits · house words in WHAT THIS IS · a header written before the holder said what the file is · the store pasted first · a large door built by hand when the job card existed · a quick header cited as a read · a full door written from pointers · the same block pasted twice · a filename typed instead of copied · RELATIONS carrying bodies instead of seeds · a fold marked CHECKED before anyone re-read it

WHAT IT IS NOT
Not the file. Not FEEDBACK, CHECKLIST or PASS-INFO copied in. Not a summary of the body. Not a test the reader must pass. Not the whole system in miniature; it's the door to it.

RAW
The top fires. The door opens. The room is behind it.

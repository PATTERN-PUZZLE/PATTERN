WHAT THIS IS
How to reach a live file without guessing, inheriting a file that
never existed, or trusting an empty fetch. It sits beside the fetch
family at root (FETCH-DIAGNOSTIC · 🔗FETCH · 🪞GITHUB-MIRRORS ·
GITHUB-FILES-PROMPT · LINKS-TRANSLATION · 🔗Basic-Lnk-COCKPIT /
GITHUB / GITLAB / RAW) and serves the SCOUT set here.

THE SIX PRINCIPLES
1. The path tells the truth; a root address guesses. Use the exact
   path.
2. A 404 isn't a verdict. Try the next door, then ask.
3. The live file is the truth; a REV- file is its memory.
4. A file's name doesn't promise its content. Read before trusting.
5. For a mind, paste beats fetch. [holder] "oaste is superior to
   fetch even if they are getting better." Fetch only when the
   holder says.
6. When fetching, raw is the door for minds; repo pages are for
   people.

ENCODING AND SIZE
Spaces → %20 · + → %2B · emoji in a name → percent-encode, or ask
for a paste · keep files a mind will fetch under about 300 KB · put
what matters at the top · an end marker lets a reader see if the
fetch was cut short.
A FRESH COPY, contradiction named, not averaged: v1.3 says append
?v=YYYYMMDD to get past a cache; STANDARDS rule 5 says pin the
commit SHA, never ?v=. The law wins until the holder rules.

THE FETCH PATH, given a filename
1. Ask for a paste.
2. If told to fetch: find the folder on the map below.
3. Build the raw address; encode the name.
4. Check the first lines, the last lines and the middle. A 200 is
   not a read.
5. Missing: try case, the REV- version, the other host.
6. Still missing: ask the holder. Don't rule it absent from here.
